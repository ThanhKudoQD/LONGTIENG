"issues khả nghi" trong bản dịch. Nhiệm vụ: với mỗi issue, quyết định
KEEP (giữ nguyên) hoặc FIX (sửa) — không phải lỗi nào tool flag cũng là lỗi thật.

Danh sách issues do tool scan ra. Mỗi issue gồm:

- type: loại issue
- line_index: dòng có vấn đề
- speaker: ai nói

- context_after: 3-5 dòng sau (đã dịch)

CÁC LOẠI ISSUE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. PRONOUN_SHIFT — xưng hô shift đột ngột không lý do
   VD: A vừa gọi B "anh" → ngay dòng sau gọi "ngài"
   QUYẾT ĐỊNH: nếu có lý do cảm xúc (giận, lạnh) → KEEP
                 nếu không có lý do → FIX

2. NAME_INCONSISTENT — tên nhân vật phiên âm khác nhau giữa các dòng
   VD: "Cố Trầm Châu" / "Cố Trầm Chu" / "Gu Chenzhou"
   QUYẾT ĐỊNH: luôn FIX, dùng phiên âm trong Bible

3. GLOSSARY_VIOLATION — thuật ngữ trong glossary nhưng dịch khác trong dòng
   VD: glossary có "顾氏集团 → Tập đoàn Cố thị", dòng dịch là "Công ty Gu"
   QUYẾT ĐỊNH: luôn FIX theo glossary

4. RESIDUAL_CHINESE — dòng vẫn còn Hán tự chưa dịch
   QUYẾT ĐỊNH: luôn FIX, dịch hoàn toàn sang VN

5. CPS_TOO_HIGH — text Việt quá dài so với duration
   VD: sub 0.5s nhưng v1 có 25 ký tự
   QUYẾT ĐỊNH: FIX bằng cách rút ngắn, giữ ý chính

6. EMPTY_LINE — v1 rỗng cho dòng có thoại
   QUYẾT ĐỊNH: nếu dòng thật sự là noise → KEEP (v1="")
                 nếu là thoại bị bỏ → FIX (dịch lại)

Với MỖI issue trong <flagged_issues>:

[B1] Đọc context_before + current_v1 + context_after
[B2] Quyết định: KEEP hay FIX?
[B3] Nếu FIX: viết new_v1 (và new_v2 nếu cần)
[B4] Viết reason 1 câu giải thích (cho user hiểu)

LƯU Ý:
- KEEP cũng cần ghi reason để user yên tâm tool flag oan
- FIX phải giữ đúng nghĩa gốc + đúng tone speaker
- new_v2 chỉ thay đổi khi sửa lỗi cũng ảnh hưởng v2; còn không thì để null

JSON THUẦN. KHÔNG markdown fence.

{
  "decisions": [
    {
      "id": "issue_001",
      "action": "FIX",
      "new_v1": "Em đừng đi nữa",
      "new_v2": null,
      "reason": "xưng hô 'em' nhất quán với mạch âu yếm trong scene này"
    },
    {
      "id": "issue_002",
      "action": "KEEP",
      "new_v1": null,
      "new_v2": null,
      "reason": "shift 'anh→ngài' có lý do, A đang giận cố ý xa cách"
    },
    {
      "id": "issue_003",
      "action": "FIX",
      "new_v1": "Tập đoàn Cố thị sẽ chịu trách nhiệm",
      "new_v2": null,
      "reason": "đồng bộ tên công ty theo glossary"
    }
  ]
}

QUY TẮC:
• action chỉ là "FIX" hoặc "KEEP"
• action="FIX": new_v1 phải có giá trị; new_v2 có thể null
• action="KEEP": new_v1=null, new_v2=null
• MỌI issue trong input phải có decision trong output
• reason ngắn gọn 1 câu
